# 语步标注平台（效度验证）

项目：基于AI农业语步语料库的学术英语教学改革研究（202502000561）

纯前端页面，用于两位标注员完成 **效度验证标注**：先做 20 句试标，再独立完成 472 句正式标注。
答案只保存在**本人浏览器**里，提交后锁定，最后由本人导出三个文件交回。

## 一、怎么用

老师会把两条链接分别发给两位标注员（链接里带口令，打开即用，不需要手输）。

- 标注员 A：`…#role=A&k=<口令>`
- 标注员 B：`…#role=B&k=<口令>`

打开后：

1. **试标（20 句）** — 必须先做完，才能解锁正式标注；
2. 与另一位标注员开一次 **30 分钟校准会**，只讨论有分歧的句子，谈定口径；
3. **正式标注（472 句）** — 逐句单选，选中才能翻到下一句；随时可回上一句修改；
4. 全部答完后点 **提交并锁定**；
5. 锁定后导出三个文件，全部发回给老师。

## 二、交回哪三个文件

| 文件 | 内容 |
| --- | --- |
| `…_正式标注.csv` | 472 行，列与老师的 Excel 完全一致（句子ID／摘要编号／语言组／期刊／年份／学科／题名／句内序号／待标句子／人工标注／备注），可直接用于计算 κ |
| `…_试标集.csv` | 20 行，同上格式 |
| `…_过程日志.json` | 每句的停留时长、进入次数、改签次数与改签轨迹、备注修改次数，以及会话信息（起止时间、设备、时区）与两个 CSV 的 SHA-256 |

> 三个文件缺一不可。日志用于说明标注过程是否正常，不参与 κ 计算。

## 三、设计约束（与纸质／Excel 版一致）

- **隔离**：页面里**不出现任何机器标注结果**；A／B 两份题库的摘要排列顺序不同，请勿互相对表。
- **强制顺序**：试标 20 句全部完成才解锁正式标注；正式标注每句必须选一个标签才能继续。
- **无总览**：页面不提供"查看所有已填标签"的列表，避免最后统一改口径。
- **提交即锁定**：点下提交后答案不可再改；导出按钮只有在提交后才出现。
- **本地保存**：答案存在本人浏览器（localStorage）里，关掉页面再打开会自动接着上次继续。
  换电脑、换浏览器或清理浏览器数据会导致答案丢失——请在一台设备上做完。

## 四、数据与版权

- 题库（试标与正式标注的句子、以及用于判断上下文的摘要全文）在仓库里以
  **PBKDF2-SHA256（200,000 次迭代）＋ AES-256-GCM** 密文存放，
  浏览器端用 WebCrypto 解密，口令只随老师发出的链接传递。
- **题库分两份**（2026-10-10 起，为首次打开提速）：`data/enc_<角色>_trial.json`（约 49 KB，
  试标 20 句＋14 篇摘要）先下载，学生立刻可以开始试标；`data/enc_<角色>_main.json`（约 459 KB，
  472 句＋80 篇摘要）在试标期间**后台静默下载**，进入正式标注前若尚未完成才显示进度。
  `data/enc_<角色>.json`（合并件）保留，供离线核验脚本比对用。
- 语料单元的著作权属原期刊与作者，本页仅供本课题组标注使用，**不对外分发摘要全文**。
- 本仓库不收集任何数据：没有后端、没有统计脚本、不发送任何请求到第三方。

```bash
# 浏览器打开 http://localhost:8080/#role=A&k=<口令>
```
